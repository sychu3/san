# 三國殺・軍爭篇（非官方 Web 實作）

5 人身份局：**1 名人類玩家 + 4 名 AI**。純前端、繁體中文、桌面與手機皆可玩。

> 本專案是非官方、非商業的規則學習用粉絲實作。三國殺及相關名稱、規則與美術權利屬於其權利人。本專案不使用官方卡圖、Logo 或卡牌掃描。

## 目前狀態（M3）

- ✅ 可完整進行一局 5 人身份局：主公 1、忠臣 1、反賊 2、內奸 1。
- ✅ 回合流程、距離、攻擊範圍、出牌、棄牌、瀕死、死亡、勝負判定。
- ✅ **完整 160 張牌全部接入對局**（標準 104 + EX 4 + 軍爭 52），預設使用完整牌堆。
- ✅ 基本牌：殺、火殺、雷殺、閃、桃、酒。
- ✅ 全部即時錦囊：無中生有、過河拆橋、順手牽羊、決鬥、南蠻入侵、萬箭齊發、桃園結義、五穀豐登、借刀殺人、火攻、鐵索連環、無懈可擊。
- ✅ 延時錦囊與判定區：樂不思蜀、兵糧寸斷、閃電。
- ✅ 全部 11 把武器（含青釭劍、寒冰劍、雌雄雙股劍、丈八蛇矛、青龍偃月刀、貫石斧、方天畫戟、麒麟弓）、4 種防具、7 匹坐騎。
- ✅ 無懈可擊連鎖、屬性傷害、鐵索傳導、火攻、酒殺、白銀獅子封頂等關鍵連招。
- ✅ 4 名 AI，只讀自己的視角，不會看到其他玩家的手牌或隱藏身份；AI 會使用全牌池與首批武將技能。
- ✅ **標準包 25 名武將技能全部接入**：首批 10 名（曹操、劉備、孫權、關羽、張飛、趙雲、黃月英、呂布、貂蟬、華佗）＋第二批 15 名（司馬懿、夏侯惇、張遼、許褚、郭嘉、甄姬、諸葛亮、馬超、甘寧、呂蒙、黃蓋、周瑜、大喬、陸遜、孫尚香）。
- ✅ 3 個主公技（護駕、激將、救援）只在該角色為主公時生效；轉化牌（武聖、龍膽、傾國、奇襲、國色、急救）走與丈八蛇矛相同的使用脈絡。
- ✅ 判定管線支援【鬼才】改判與【天妒】取得判定牌；【觀星】、【洛神】在準備階段運作。
- ✅ **AI 3 難度（新手／進階／高手）與身份推理**：只依公開事件更新「疑似反賊」信念（朝主公出手等於明確敵意，即使被【閃】掉也算），反賊不會攻擊已曝露的同夥、忠臣不會攻擊救過主公的人，高手會用手牌推測；介面右上角可切換。
- ✅ **仁德與空城判斷**：AI 不會一次把手牌給光（一般每次 2 張、每回合最多 4 張並保留至少 1 張）；不會破壞隊友【空城】，只有敵人 0 手牌【空城】且同回合有【殺】／【決鬥】能跟上時，才給 1 張低價值牌破防。內奸只在中低血量且缺牌時給主公 1 張，不把主公治療到滿血。
- ✅ **裝備與【酒】順序**：裝備不是一律先裝；新武器／`(-1)` 馬只在能解鎖或強化本回合攻擊時提前，且不會用較差的裝備蓋掉現有裝備。【酒】會排在同回合的【殺】之前，沒有後續【殺】時保留。敵意牌不會指向已知隊友（即使新手難度的隨機擾動也不會）。
- ✅ **技能目標合理性**：需要指定目標的技能（突襲、離間、反間、青囊、結姻、仁德、借刀殺人、多目標【殺】）與代打請求（激將、護駕）都先判斷敵我，不會把技能指向隊友。
- ✅ **存檔與重播**：只存 seed、難度與人類回應到 `localStorage`；讀檔可播放／暫停／單步／跳到最後。損壞或版本不相容會拒絕載入。
- ✅ **設定與音效**：合成音效（預設關閉）、動畫速度（完整／快速／關閉）、**佈景主題（深色／淺色／跟隨系統）**；設定只存本機。
- ✅ **UX 與無障礙**：受傷閃動、瀕死提示、鍵盤焦點、Esc 關閉彈窗、`prefers-reduced-motion`、手機直向堆疊版面（其他角色在上，自己的武將與行動按鈕相鄰放在最下方）。
- ✅ **逐步模式**：每個 AI 行動前暫停並顯示「繼續」，方便看清 AI 做了什麼；可隨時開關。
- ✅ **日誌分段與滑鼠提示**：每個角色回合有分隔線、行動列依勢力上色；卡牌與技能滑過顯示效果說明，坐騎標示 `(+1)`／`(-1)`。
- ⏳ 尚無線上多人。

## 試玩

### 方式 1：本機開發模式（最快）

需求：Node.js 20.19 以上（建議 Node 22 LTS）與 npm 11。

```bash
npm ci
npm run dev
```

終端機會顯示：

```text
VITE v6.4.5  ready in 152 ms
➜  Local:   http://127.0.0.1:5173/
```

用瀏覽器打開 <http://127.0.0.1:5173/> 即可開始。這個終端機要維持開啟，按 `Ctrl+C` 停止。

### 方式 2：Production build 預覽

```bash
npm run build
npm run preview
```

預覽伺服器預設在 <http://127.0.0.1:4173/>。這個模式會使用與正式部署相同的 CSP，適合確認沒有 console error。

### 方式 3：部署成靜態網站

```bash
npm run build
```

把 `dist/` 上傳到任何靜態主機即可（Netlify、Cloudflare Pages、Vercel、GitHub Pages）。`dist/_headers` 與 `vercel.json` 已包含安全標頭；若主機不支援，請在該主機另外設定，詳見 [SECURITY.md](./SECURITY.md)。

產出約 330 KB（JS 約 296 KB、CSS 約 20 KB），任何免費靜態方案都放得下。

#### Cloudflare Pages（建議的公開部署方式）

免費方案不限流量／請求數，且**完整支援 `dist/_headers`**，`public/_headers` 裡的 CSP（含 `frame-ancestors 'none'`）、`X-Frame-Options`、`nosniff` 都會生效。

**Dashboard 上傳（不用安裝任何工具）**

```bash
npm run build
```

到 <https://dash.cloudflare.com> 註冊免費帳號（不用信用卡）→ Workers & Pages → Create → Pages → **Upload assets** → 專案名稱例如 `sanguosha` → 把 `dist/` 整個資料夾拖上去 → Deploy。完成後網址是 `https://sanguosha.pages.dev`；改版時再拖一次新的 `dist/` 即可。

**CLI（可重複部署）**

```bash
npm run build
npx wrangler@4 pages deploy dist --project-name sanguosha
```

第一次會開啟瀏覽器請你授權，憑證存在本機 `~/.wrangler`。`wrangler` 以 `npx` 一次性執行，不會寫進專案依賴或 lockfile。

**部署後驗證**

```bash
curl -sI https://sanguosha.pages.dev/ | grep -iE "content-security|x-frame|nosniff|referrer"
```

應看到 `_headers` 的完整內容；之後開遊戲確認 console 沒有 CSP violation。

#### 其他主機

- **Netlify／Vercel**：支援自訂標頭（`_headers`／`vercel.json`），免費方案足夠，`vercel.json` 已備好。
- **Surge／GitHub Pages**：可以上線，但**不支援自訂 HTTP 標頭**，只剩 `index.html` 內的 CSP meta，少了 `frame-ancestors` 與 `nosniff`。
- **tiiny.site 等免費拖放主機**：平台會做內容政策審查（卡片遊戲常被誤判），實測上傳被拒；不建議使用。

差異與取捨詳見 [SECURITY.md](./SECURITY.md) 3.6。

### 第一次試玩怎麼做

1. 你是畫面下方標示「你」的角色；其他四席由 AI 操作。
2. 不熟悉規則時，先按右上角「規則」查看摘要。預設為「逐步」模式：每次 AI 行動前會暫停，按右側「繼續」讓 AI 行動；想連續看可按右上角「逐步」關閉。想換配色可按「主題」循環切換深色／淺色／跟隨系統，或到「設定」裡選。
3. 把滑鼠移到卡牌、裝備、判定牌或武將技能上，會顯示效果說明；坐騎名稱有 `(+1)`／`(-1)`。
4. 出牌階段，右側「行動」會列出所有合法選項。每個選項已包含目標，直接按下去即可。
5. 使用【鐵索連環】、【貫石斧】等需要選牌的牌時，先按行動選項，再從下方手牌點選指定張數，最後按「確認選擇」。武將技能（仁德、制衡、青囊、離間）也使用同一種流程。
6. 進入棄牌階段時，點擊下方手牌選取，再按「確認選擇」。被選中的牌會浮起並顯示勾號。
7. 別人對你使用【殺】時，右側會詢問是否打出【閃】；沒有【閃】就按「不出」。
8. 錦囊結算前，若你有【無懈可擊】，右側會詢問是否抵消；也可以連環抵消別人的無懈可擊。
9. 角色旁邊的「判定」區會顯示樂不思蜀、兵糧寸斷、閃電等延時錦囊。
10. 你瀕死時，可以用【桃】或【酒】自救；其他角色也可能救你。
11. 想重來按右上角「新局」。畫面會顯示本局 `seed`，相同 seed 可重現同一局。
12. 「上帝視角」只供除錯，會顯示所有身份與手牌，不影響 AI 判斷。

手機直向（窄螢幕）時版面改成單欄：其他四名角色在上方，接著是「你的手牌」，然後是你自己的武將，最後才是行動／確認按鈕——查看自己體力與裝備時不必再往上捲。

一局的目標：依你的身份取勝。主公／忠臣要消滅反賊與內奸；反賊要殺主公；內奸要最後單挑獲勝。

## 疑難排解

| 症狀 | 處理 |
|---|---|
| `node: command not found` | 安裝 Node 22 LTS，或把 portable Node 的 `bin` 加入 `PATH` |
| `npm ci` 出現 arborist／peer 錯誤 | 使用 npm 11：`npx --yes npm@11.6.2 ci`；本專案 `packageManager` 已指定 `npm@11.6.2` |
| 5173 連接埠被占用 | `npm run dev -- --port 5174` |
| 畫面空白 | 打開瀏覽器 DevTools console 查看錯誤；先跑 `npm run build` 確認 TypeScript 無誤 |
| 想從另一台電腦連線 | `npm run dev -- --host 0.0.0.0`，但 dev server 沒有驗證，只可在可信任的內網使用；公開展示請用 build 後的靜態主機 |
| 想讓同網段的手機／電腦一起玩 | `npm run build && npm run preview -- --host 0.0.0.0 --port 4173`，其他裝置開 `http://<你的內網 IP>:4173/`（例如 `192.168.0.220`） |
| 部署後畫面空白（404） | 上傳的必須是 `dist/` **內容**（最上層是 `index.html`），不是多一層的 `dist/` 資料夾 |
| 部署後安全標頭沒生效 | 該主機需支援 `_headers`／`vercel.json`；Cloudflare Pages 與 Netlify 支援，Surge／GitHub Pages 不支援 |
| 看不到其他玩家的手牌 | 這是正常的，隱藏資訊由 `viewFor()` 遮蔽；只有「上帝視角」會顯示 |

## 常見規則疑問

- **為什麼用完一張【殺】後，不能攻擊下一位？** 每回合只能使用一張【殺】。旁邊角色死亡後，下一位存活角色的距離確實會變成 1，但同一回合要連續攻擊，必須裝備【諸葛連弩】。
- **旁邊角色死了還是打不到下一位？** 請看行動選項上的「距離／範圍」。若目標裝備 +1 馬，距離會 +1；死亡角色本身不佔距離。
- **為什麼【桃】不能補別人？** 出牌階段【桃】只能對自己使用；要救其他角色，只能在該角色瀕死時使用。
- **為什麼我的錦囊被抵消了？** 任何角色都可以在錦囊結算前使用【無懈可擊】。若有人再用【無懈可擊】抵消它，原錦囊就會恢復結算；連鎖次數為奇數時原錦囊無效。
- **鐵索連環怎麼用？** 使用後選擇 1–2 名角色切換橫置狀態；也可在行動選項選「重鑄」棄掉它並摸一張。橫置角色受到火焰或雷電傷害時，會把同數值、同屬性的傷害傳給其他橫置角色。
- **選項太多看不完？** 行動清單可捲動，「結束出牌階段」固定在清單下方。丈八蛇矛已改為先選目標、再選兩張手牌，不會一次列出所有手牌組合。

## 操作方式

1. 出牌階段會在看板右側顯示合法行動，按按鈕即可執行。
2. 需要棄牌或選牌時，點擊下方手牌，再按「確認選擇」。
3. 需要拆牌或偷牌時，可以選擇目標的裝備／判定牌，或盲選一張手牌。
4. 右上角「新局」重新開始；「規則」可查看摘要。

## 專案結構

```text
src/
  data/         卡牌與武將靜態資料（160 張完整牌表）
  engine/       純 TypeScript 遊戲引擎（不依賴 React）
    types.ts    型別、Request/Response、GameView
    events.ts   時機／hook 系統（不需請求的內部觀察）
    skills.ts   武將技能宣告與查詢（標準 25 名）
    engine.ts   回合流程、出牌結算、傷害、瀕死、勝負
    state.ts    建立對局、抽牌、棄牌、視角遮蔽
    rules.ts    距離、攻擊範圍、手牌上限
    rng.ts      可重現的 mulberry32 隨機數
  ai/           只讀 PlayerView 的 AI 決策
  game/         generator 驅動器與自動對局
  ui/           React 元件
  tests/        Vitest 測試與模擬
public/
  _headers      Netlify / Cloudflare Pages 安全標頭
```

引擎與 UI 分離：`runGame()` 是 generator，透過 `Request` / `Response` 與驅動器溝通。UI 只拿到 `GameView`，隱藏資訊由 `viewFor()` 遮蔽。

## 安全設計

本專案以 security by design 開發，重點包括：

- 生產環境 CSP：`default-src 'self'`、`script-src 'self'`、`connect-src 'none'`，不允許 inline script、外部 CDN 或連線。
- React 預設 escaping；不使用 `dangerouslySetInnerHTML`，不接受 HTML 字串。
- `viewFor()` 遮蔽其他玩家的手牌與未公開身份；AI 只取得自己的 `PlayerView`。
- 日誌會遮蔽隱藏資訊：從手牌偷走的牌只記錄「一張手牌」，不公開牌名。
- `GameController.respond()` 驗證 request id 與等待中的玩家，拒絕過期或偽造回應。
- 引擎驗證卡牌 id、目標 id、選牌數量與合法選項；非法輸入會拋錯而不是默默套用。
- 回合上限 500、單一階段請求上限 4,000、無懈可擊連鎖上限 16、模擬請求上限 800,000、紀錄上限 500 行，避免死循環與無界成長。
- 全牌池 AI 1,000 局模擬作為測試關卡，確認新牌不會造成崩潰或死循環。
- 精確鎖定依賴版本、提交 `package-lock.json`、`npm audit` 0 漏洞；不使用 CDN 或遠端字型。
- `.npmrc` 啟用 `ignore-scripts`，安裝依賴時不執行套件安裝腳本。
- 不收集資料、不使用 cookie、不上傳任何內容；`localStorage` 只用來存本機存檔與顯示設定，且 `connect-src 'none'` 確保執行期不會發出任何網路請求。

完整威脅模型與部署標頭請見 [SECURITY.md](./SECURITY.md)。
